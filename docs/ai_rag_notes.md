# AI & RAG Concepts — Quick Notes

## What is an LLM?
- LLM stands for Large Language Model
- Trained on large amounts of text data to predict the next token
- Examples: Gemma, Llama, GPT, Claude
- Runs locally via Ollama on Apple Silicon — no cloud needed
- Responds to prompts with generated text based on patterns learned during training

## What is RAG?
- RAG stands for Retrieval-Augmented Generation
- Combines document retrieval with LLM generation
- Solves the problem of LLMs not knowing your private or recent documents
- Instead of relying on training data alone, the model is given relevant context at query time

## How RAG works
- Step 1 — Ingestion: load documents from disk and split into chunks
- Step 2 — Retrieval: find the chunks most relevant to the user's question
- Step 3 — Generation: send the relevant chunks + question to the LLM as a prompt
- Step 4 — Response: LLM answers using the provided context, not just its training data

## What is a chunk?
- A chunk is a small piece of a larger document
- Typical size is 500–1000 characters
- Smaller chunks are more precise but may lack context
- Larger chunks carry more context but may include irrelevant content
- Overlap between chunks prevents important sentences being split at a boundary

## What is a token?
- A token is the smallest unit an LLM processes — roughly 3/4 of a word on average
- "hello world" is approximately 2 tokens
- LLMs have a context window limit measured in tokens (e.g. 8k, 32k, 128k)
- Staying within the context window is why chunking matters

## What is a prompt?
- A prompt is the full text sent to the LLM
- In RAG, a prompt has three parts: system instruction + retrieved context + user question
- The system instruction tells the model how to behave
- The context is the retrieved chunks pasted in
- The question is what the user actually asked

## What is a vector embedding?
- A numerical representation of text as a list of floating point numbers
- Similar meaning = similar numbers = close together in vector space
- Used in Phase 2 for semantic search — finding chunks by meaning, not just keywords
- Generated by an embedding model (nomic-embed-text in Phase 2)

## What is hybrid retrieval?
- Combines keyword search (BM25) and semantic search (vector embeddings)
- BM25 is good at exact matches — product names, codes, proper nouns
- Vector search is good at meaning — synonyms, paraphrases, related concepts
- Hybrid covers both failure modes — Phase 2 of this project
